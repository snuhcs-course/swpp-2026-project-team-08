## 실행과 보고서

c8은 테스트가 앱 코드를 얼마나 실행했는지 측정한다. 테스트 구성과 작성 기준은 [test.md](test.md)를 따른다.
아래 명령은 모두 `client/`에서 실행한다.

전체 테스트를 한 번 실행하고 계층별 커버리지와 테스트 실행 결과를 남긴다. 보고서는 Git에 저장하지 않는다.
잠금 파일에 고정한 의존성을 설치한 뒤 실행한다.

```sh
npm ci --ignore-scripts
npm run test:coverage
```

`tests/` 바로 아래와 `unit/`, `integration/`의 테스트를 함께 실행한다.
`npm test`는 테스트만 실행하고, `npm run test:coverage`는 같은 범위를 측정하여 보고서를 만든다.
실행할 때 이전 측정의 보고서와 기존 unit·integration·combined 출력 폴더를 교체한다.
테스트가 실패해도 수집한 기록으로 보고서를 만들며, 명령은 실패 종료 코드를 반환한다.

   Node의 JavaScript 실행 엔진인 V8이 실행한 코드 범위와 횟수를 임시 폴더에 기록한다.
2. 테스트가 TS·TSX 파일을 읽을 로더를 등록한다. 공통 로더는 [register.cjs](helpers/register.cjs)이다.

3. 앱 파일을 불러올 때 로더가 TypeScript의 `transpileModule()`을 호출해 JavaScript로 바꾼다.
   변환 결과는 별도 `.js` 파일로 저장하지 않는다.
4. Node가 변환된 앱 코드를 실행하고, V8이 실행 기록을 남긴다.
5. c8이 로더의 소스맵을 이용해 기록을 원래 TS·TSX 위치에 연결한다.

6. 스크립트가 c8의 측정 결과를 메모리에서 계층별로 합산해 HTML을 만들고 임시 기록을 삭제한다.

## 측정 설정

설정 파일은 [`.c8rc.json`](../.c8rc.json)이다. 실행 스크립트가 이 파일을 읽어 c8에 측정 범위를 전달한다.

| 설정 | 현재 값 | 의미 |
|---|---|---|
| `all` | `true` | 테스트가 불러오지 않은 대상 파일도 미실행으로 포함한다. |
| `src` | `["src"]` | 측정할 소스를 `src/`에서 찾는다. |
| `include` | `["src/**/*.ts", "src/**/*.tsx"]` | 앱의 TS·TSX 파일을 포함한다. |
| `extension` | `[".ts", ".tsx"]` | 측정할 파일 확장자를 지정한다. |
| `exclude` | 아래 제외 범위 표의 패턴·경로 | 타입 파일과 표시용 리소스를 모든 커버리지 지표의 집계에서 제외한다. |
| `exclude-after-remap` | `true` | 실행 위치를 원본 파일에 연결한 뒤 제외 규칙을 적용한다. |
| `reporter` | `[]` | c8 기본 보고서를 생성하지 않는다. 계층별 HTML은 실행 스크립트가 직접 만든다. |
| `reports-dir` | `coverage` | 최종 HTML과 테스트 로그를 저장한다. 실행 스크립트는 이 전용 경로만 교체한다. |


### 제외 범위

| 종류 | 패턴·경로 (`client/` 기준) |
|---|---|
| 선언 파일 | `**/*.d.ts` |
| 타입 파일 | `src/**/types/**`, `src/**/types.{ts,tsx}`, `src/**/*Types.{ts,tsx}` |
| 표시용 리소스 | `src/util/colors.ts`, `src/util/fonts.ts`, `src/util/strings.ts` |

제외는 파일 전체에 적용한다. 타입 파일 안의 변환 함수·상수도 커버리지 계산에서 제외한다.
해당 함수의 동작은 테스트로 검사하며, 타입의 일관성은 `tsc --noEmit`으로 검사한다.
커버리지 제외 설정은 테스트 실행 범위를 바꾸지 않는다.

## 지표 읽기

각 지표는 `한 번 이상 실행한 항목 수 / 측정 대상 항목 수 × 100`으로 계산한다.

| 지표 | 의미 |
|---|---|
| Lines | 변환 전 .ts 파일의 line 중 실행된 것으로 기록된 비율 |
| Functions | 측정된 함수 중 한 번 이상 호출한 함수의 비율 |
| Branches | 실행 중 갈라지는 코드 경로 가운데 측정기에 기록되고 실제 실행된 경로의 비율 |

| 계층 | 파일 기준 (`src/` 기준) |
|---|---|
| Data | `data/` 전체 |
| Hooks and Providers | `providers/`, 경로에 `/hooks/`가 있거나 이름이 `Provider.ts(x)`·`Context.ts(x)`로 끝나는 파일 |
| UI and routes | `app/**`, `components/**`, `**/screens/**`, `**/components/**`에 있는 측정 대상 TS·TSX 파일. 하단 측정 범위 참고 |
| Utilities | 제외된 리소스를 뺀 `util/` 파일 |
| Rules | `rules/`, 기능별 `rules.ts(x)`, `features/onboarding/draftSaveGate.ts`·`navigation.ts` |

### UI and routes의 측정 범위

이 분류는 라우트·레이아웃, 화면, 공통·기능별 컴포넌트를 파일 단위로 측정한다.
화면 표시뿐 아니라 해당 파일 안의 로컬 상태, 파생값 계산, 이벤트 처리, Hook·Provider 호출, 저장·인증 호출과 화면 이동도 포함한다.

새 측정 대상 파일이 어느 분류에도 속하지 않으면 보고서 생성이 실패한다.
파일의 책임에 맞춰 실행 스크립트의 `layerFor()`와 이 표를 함께 수정한다.
