## 2. 검증 경계

- **공통 UI / 기능:** 공용 Unit은 입력 전달·비활성 버튼·삭제 대상 전달 계약을, 온보딩 Unit은 답변 규칙을 검사한다. Integration은 UI 행동이 실제 답변에 반영되는지 확인한다. 공통 컴포넌트가 소유한 규칙은 기능 Unit에 복제하지 않는다.
- **Navigation / completion:** Unit은 목적지 판단·완료 조건 조합·독립 처리 제어, Integration은 실제 버튼 연결·저장 요청·상태·목적 화면을 확인한다. 검토 수정 이동은 `review-edit`가 담당한다. 앱 공통 로그인 분기·딥링크·뒤로 가기 규칙은 별도 기능에 둔다.
- **초안:** 아래 모든 단계의 정상 저장·새 실행에서의 복원을 확인한다. 화면 왕복만으로 저장을 증명하지 않는다. 공통 실패·지연은 대표 사례로, 화면별 차이만 추가한다.

| 저장·복원 대상 | 보존할 값 |
|---|---|
| 동의 | 필수·선택 동의의 참/거짓, 선택 동의 거부값. |
| 자녀 정보 | 닉네임·연령대와 일부만 입력한 미완성 상태. |
| 알레르기 / 식이 제한 | 각 질문의 목록과 미응답·없음·선택 상태를 독립적으로 보존. |
| Dietary Pattern | 미응답·특정 유형 없음·선택값. 7개 값의 상세 변환은 Unit 담당. |
| Safe Foods | 음식·부가 정보·아직 Add하지 않은 입력. 없음 관련 값은 D2 확인. |
| 검토 | 현재 단계·최신 답변, 재개 후 수정 시 다른 답변 보존. |

- **증명 범위:** 라우터 mock은 이동 요청까지만, HTTP mock은 클라이언트 처리까지만 확인한다. 실제 도착은 라우터·진입 조건·목적 화면을 연결해야 하며, 서버 DB 저장은 별도 검증이다. Hook 직접 호출은 UI 연결을 증명하지 않는다. 기기 의존 키보드·포커스·뒤로 가기는 별도 기기 확인 대상이다.
- **유용성:** 사례마다 요구사항과 잡을 오류를 적고, 정상·실패·재시도는 같은 행동 파일에 묶는다. 기대값을 대상 함수로 계산하거나 코드 문자열·내부 호출·전체 화면 스냅샷만으로 행동을 증명하지 않는다. 같은 입력 조합은 사례 표로 묶고 개수보다 서로 다른 오류 탐지를 본다.
- **실패 검사 제안:** 저장·읽기 실패와 연속 저장 순서는 데이터 유실 방지 검사다. 미정인 오류 문구·재시도 UI·미저장 입력 복구 범위를 새 요구사항으로 만들지 않는다.

## 4. 현재 배치

- `unit/onboarding-rules.test.cjs`에는 계정·비밀번호 검사를, 기존 `integration/onboarding-flow.test.cjs`와 `onboarding-provider.test.cjs`에는 프로필 편집을 포함한 검사를 유지한다. 한 테스트에 섞인 검증은 임의로 끊지 않는다.
- `abc-design-ui.test.cjs`의 온보딩 검토·진행 표시·선택지 ID 검사는 각각 `review`·`navigation`·`profile-api`에 둔다. 단순 단계 계산은 Unit이며 실제 화면 이동 검증으로 세지 않는다.
- 실행 준비는 `helpers/onboarding-flow.cjs`·`helpers/onboarding-provider-harness.cjs`에 둔다. `helpers/onboarding-screen.cjs`는 RN Web·jsdom에서 실제 Expo Router와 온보딩 화면을 연결하며, 기기 배치·터치는 검증하지 않는다.
- 일반 테스트와 커버리지는 `unit/`·`integration/` 하위 폴더를 재귀 탐색하며 예시 폴더는 별도 실행한다.

후속 보강은 위 목표와 실제 검증문을 대조해 한 행동씩 진행한다. 미확정 명세는 테스트 기대값을 바꾸기 전에 해결한다.
