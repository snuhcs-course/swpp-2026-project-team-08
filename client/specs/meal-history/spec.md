# Meal History

## Goal

보호자가 날짜·음식·재료로 식사 기록을 찾고, 미완료 기록을 이어 작성하며,
식사별 사진·Outcome·연결된 추천을 확인한다. 필요 없는 기록은 확인 후 삭제한다.
리뷰한 식사에서는 추천 화면으로 이동해 추천을 생성하거나 미처리 추천을 확인한다.

## User Flow

1. 보호자가 Meal History를 열어 월별 달력과 저장된 식사 목록을 확인한다.
2. 작성 중인 식전 초안이 있으면 Continue Logging의 Resume으로 재개 확인 후 이어 작성한다.
3. 날짜를 선택하거나 음식·재료를 검색하고, 필요하면 Unreviewed logs only를 켠다.
4. 식사 카드를 눌러 사진·음식별 결과·제공 정보가 있는 상세 화면을 연다.
5. 리뷰 전 식사는 Continue Review로 식후 리뷰를 작성한다.
6. 연결된 추천이 있는 음식은 Linked Suggestion으로 추천을 확인하고 같은 카드로 돌아온다.
7. 추천 진입 조건을 만족하는 식사는 View Suggestion으로 추천 화면을 열어 추천을 처리한다.
8. 삭제할 식사는 메뉴에서 Delete Meal Record를 누르고 확인 후 삭제한다.

## Requirements

### R1 — Continue Logging

1. 현재 자녀의 로컬 식전 초안 한 개를 조회한다. 초안이 없거나 단계가 complete이면 영역을 숨긴다.
2. 날짜·유형, Draft, 첫 번째 이름 있는 음식과 Resume을 표시한다.
   유형이나 음식 이름을 아직 입력하지 않았으면 해당 정보는 생략한다.
3. 저장된 Meal ID가 없는 초안에서 Resume을 누르면 Meal Check-in의 재개 확인 화면을 연다.
   이어 작성을 선택하면 저장된 단계와 입력값을 복원한다.
4. 표시 중인 초안에 저장된 Meal ID가 있으면 Resume은 해당 식사의 식후 리뷰 화면을 연다.
5. 식전 기록을 저장하면 초안은 complete가 되어 이 영역에서 숨겨진다.
   저장된 식사의 리뷰 대기는 식사 목록에 Awaiting Review로 표시하며, 상세의 Continue Review로 진입한다.

### R2 — 달력과 날짜 선택

1. 기록 유무와 관계없이 월별 달력을 표시한다. 월·연도 선택과 이전·다음 월 이동을 제공한다.
2. 날짜별 저장 기록 수를 1개, 2개, 3개 이상으로 구분해 표시하고 선택 날짜를 표시한다.
3. 날짜를 선택하지 않으면 표시 중인 월과 관계없이 모든 날짜의 기록을 조회한다.
   달력의 월만 바꿔도 식사 목록을 해당 월로 제한하지 않는다.
4. 날짜 하나를 선택하면 그 날짜의 기록을 표시한다. 다른 날짜를 누르면 선택과 결과를 즉시 바꾼다.
5. 선택한 날짜를 다시 누르거나 Clear를 누르면 날짜 선택을 해제하고 전체 날짜로 돌아간다.
   시작일·종료일 범위 선택은 제공하지 않는다.
6. 최초 진입은 오늘 날짜와 현재 월을 선택한다. 진입 경로에 유효한 오늘 이전 또는 오늘의 날짜가
   있으면 해당 날짜와 월을 선택한다. 잘못된 날짜나 미래 날짜가 전달되면 오늘로 시작한다.
7. 월 이동 범위는 1900년 1월부터 현재 월까지이며 미래 날짜는 선택할 수 없다.
   월만 바꾸어도 이미 선택한 날짜는 유지한다. 날짜 선택을 해제해야 전체 날짜를 조회한다.
8. 달력의 기록 수에는 전체 저장 식사 수를 보여준다.

### R3 — 검색과 리뷰 필터

1. 음식명과 재료명으로 식사 기록을 검색한다.
   검색 아이콘 또는 키보드 Search를 누르면 앞뒤 공백을 제거한 검색어로 검색한다.
   대소문자를 구분하지 않는 부분 일치이며, 식사 유형·추천 문구는 검색 대상이 아니다.
   입력 중인 검색어는 제출 전까지 결과에 적용하지 않는다.
2. 날짜·검색어·Unreviewed logs only 조건은 함께 적용한다.
   날짜를 선택했으면 해당 날짜에서, 선택하지 않았으면 전체 날짜에서 검색한다.
3. Unreviewed logs only를 켜면 다른 검색 조건을 만족하는 리뷰 대기 식사만 표시한다.
   끄면 리뷰 완료와 리뷰 대기 식사를 모두 포함한다.
4. 검색창을 비우거나 공백만 남기면 제출하지 않아도 즉시 검색 조건을 해제한다.
   날짜와 리뷰 필터는 유지한다.
5. 검색 범위를 표시한다. 제출한 검색어가 있고 목록이 펼쳐져 있으면 일치하는 식사 수를 표시한다.
   키보드가 열려도 검색 입력창을 볼 수 있어야 한다.

### R4 — 식사 목록과 빈 상태

1. 검색 조건에 맞는 저장된 식사는 식사 날짜 내림차순으로 표시한다. 같은 날짜이면 숫자 Meal ID가 큰 식사를 먼저 표시한다.
2. 카드에는 식사 유형·날짜·요일, 음식 요약, Reviewed 또는 Awaiting Review 상태를 표시한다.
3. 썸네일은 식전 사진, 식후 사진, 기본 아이콘 순서로 선택한다.
4. 카드를 누르면 해당 Meal ID의 상세 화면을 연다.
5. 목록이 비어 있고 제출한 검색어가 있으면 해당 검색어를 포함한 검색 결과 없음 안내를 표시한다.
   전체 저장 기록의 유무와 관계없이 검색어가 있는 경우에는 이 안내를 표시한다.
6. 목록이 비어 있고 검색어가 없으면 Please record your meal, Saved meals will show up here를 표시한다.
   Go to Meal Check-in은 전체 저장 식사가 없고 검색어도 없을 때 표시한다.
   날짜·리뷰 필터로 목록이 비어도 달력과 검색 조건은 유지한다.
7. Go to Meal Check-in은 `/meal-checkin`을 연다. 복원할 식전 초안이 있으면 재개 확인을 거친다.
   complete 초안이 남아 있으면 해당 완료 화면을 열고, 초안이 없으면 새 기록을 시작한다.
8. 네이티브 목록은 검색·필터를 상단에 고정한 바텀시트다. 최초 진입·복귀 시 최소 높이에서
   검색창·날짜 범위·리뷰 필터만 보여주고, 확장하면 목록·결과 수·조회 상태를 표시한다.
   최소·중간·화면 90%의 세 높이를 제공한다. 웹은 펼쳐진 목록을 표시한다.
9. 다른 화면으로 이동하기 전에 네이티브 시트를 닫고, 이동 중 추가 클릭은 무시한다.
   화면에 돌아오면 다시 이동할 수 있다.
10. 화면 포커스 복귀와 달력 영역의 당겨서 새로고침은 식사 목록·식전 초안을 다시 조회한다.
    목록 시트 자체에서는 당겨서 새로고침하지 않는다.
11. 펼친 목록은 최초 조회 중 진행 표시를, 조회 실패 시 오류와 Retry를 표시한다.
    재조회에 실패하면 목록 대신 오류를 표시한다. Retry는 식사 목록과 식전 초안을 다시 조회한다.

### R5 — 식사 상세와 리뷰 재개

1. 식사 날짜·요일·유형·장소, 리뷰 상태와 식전·식후 사진을 표시한다.
2. 식전 사진은 왼쪽, 식후 사진은 오른쪽에 각각 이름과 함께 표시한다.
   사진이 없으면 해당 영역에 기본 아이콘을 표시한다.
3. 음식별로 이름, 재료, 조리 방법, 추가 설명, 수용도, 식후 반응과 어려움의 이유를 표시한다.
4. 리뷰가 있는 식사에서 저장된 결과가 null이 아닌 재료는 음식 카드 뒤에 별도 결과 카드로 표시한다.
   재료 카드에는 소속 음식명·식후 결과·어려움의 이유를 표시한다.
   결과가 null인 재료는 음식 카드의 재료 목록에만 표시한다.
5. 식후 리뷰가 없으면 Awaiting Review와 Continue Review를 표시한다.
   Continue Review는 해당 식사의 식후 리뷰를 연다. 리뷰가 있으면 Reviewed를 표시하고
   Continue Review는 숨긴다.
6. 결과가 입력되지 않은 음식은 No record로 표시한다.
7. 식사의 리뷰 여부는 저장된 음식 결과로 판단한다. 모든 음식 결과가 null이거나 음식이 없으면
   리뷰 없음이며, 음식 하나라도 결과가 있으면 Reviewed다. 일부 음식의 No record와 Reviewed가
   함께 표시될 수 있다. 재료 결과나 식후 사진만으로 Reviewed로 판단하지 않는다.
8. 첫 번째 결과 카드는 펼쳐서, 나머지는 접어서 표시한다. 카드 제목을 누르면 펼침 상태를 전환한다.
   펼친 카드에서 재료·수용도·어려움의 이유·연결 추천을 확인한다.
9. 수용도 막대는 식후 결과를 시각화한다.
   Eaten 100%, Tasted 55%, Unclear 35%, Untouched 12%, No record 0%로 표시한다.
   이 비율은 실제 섭취량이나 사용자가 입력한 수용도 점수를 나타내지 않는다.
10. 최초 상세 조회 중에는 진행 표시를 보여준다. 조회 실패·찾을 수 없는 식사·잘못된 식사 ID에는
    오류와 Retry를 표시한다. 재조회 실패 시 상세 대신 오류를 표시하고 Retry로 상세를 다시 조회한다.

### R6 — Linked Suggestion

1. Linked Suggestion은 해당 음식에 시도한 추천을 연결한 기록이다.
   식사 상세의 음식별 recommendation_tries에서 연결을 읽는다.
2. 같은 음식에 연결된 추천이 여러 개이면 서버 응답의 첫 연결 한 개를 표시한다.
   연결이 있는 음식 카드를 펼치면 Linked Suggestion을 표시한다.
3. Linked Suggestion을 누르면 같은 카드에서 음식명, What to try, Why this may help,
   Serving Tip을 표시한다. Serving Tip 내용이 없으면 제목만 표시한다.
4. Go back to meal을 누르면 같은 음식의 식후 결과 면으로 돌아간다.
5. 재료 결과 카드에는 Linked Suggestion을 표시하지 않는다.
6. 식사 상세의 연결 추천에는 북마크와 저장·해제 동작을 표시하지 않는다.
7. View Suggestion은 해당 식사를 근거로 생성하는 추천 화면을 연다. 표시 조건은 R8을 따른다.

### R7 — 식사 기록 삭제

1. 상세 화면의 더보기 메뉴에서 Delete Meal Record를 누르면 삭제 확인을 연다.
2. 확인에는 삭제할 식사의 날짜·유형과 되돌릴 수 없다는 안내를 표시한다.
   메뉴나 확인창을 여는 것만으로 삭제하지 않는다.
3. Cancel을 누르면 기록을 보존하고 확인창을 닫는다.
4. 서버의 식사·음식·재료 삭제와 로컬 식사·식후 기록 정리를 완료하면 날짜를 전달하지 않고
   `/section/mealLog`로 이동한다. 새 목록은 오늘·현재 월·빈 검색어·리뷰 필터 꺼짐으로 시작한다.
5. 삭제한 식사의 음식을 원본으로 생성한 추천은 저장 상태와 관계없이 삭제한다.
   그 추천에 연결된 시도 기록도 다른 식사의 시도를 포함해 함께 삭제한다.
6. 다른 식사에서 생성된 추천을 이 식사에서 시도한 경우, 이 식사의 시도 기록을 삭제한다.
   마지막 시도가 사라진 TRIED 추천은 SAVED로 되돌리고, 다른 시도가 남아 있으면 상태를 유지한다.
7. 삭제 요청 중에는 확인창의 Delete·Cancel과 닫기를 비활성화하고 진행 상태를 표시한다.
   서버 요청이나 로컬 정리에 실패하면 확인창에 오류를 표시하고 다시 삭제하거나 취소할 수 있다.
8. 사진 URI를 담은 식사 기록은 삭제하며 사진 파일 자체는 삭제하지 않는다.

### R8 — View Suggestion 위치와 표시 조건

1. Meal Detail의 사진 위 리뷰 상태 행 오른쪽에 Continue Review와 같은 디자인으로 버튼을 표시한다.
   Continue Review와 View Suggestion은 같은 위치를 사용한다. 식사 목록에는 별도 버튼을 추가하지 않는다.
2. 표시 조건은 [Home의 View Suggestion 기준](../home/spec.md#r7--view-suggestion)과 동일하다.
3. 식후 리뷰가 없거나 추천 대상 음식이 없으면 버튼을 표시하지 않는다.
4. 버튼을 누르면 현재 상세 화면의 Meal ID로 `/recommendation/[mealId]`를 연다.
5. 빠른 연속 클릭으로 같은 추천 화면이 여러 번 열리지 않는다.
   추천 화면에서 돌아온 뒤에도 R8의 표시 조건을 만족하면 다시 진입할 수 있다.

## Edge Cases

- 식전 초안이 없거나 complete임. 표시 중인 초안에 저장된 Meal ID가 있음 (R1)
- 진입 날짜가 잘못되었거나 미래임. 날짜 선택 없이 월만 바꾸거나 선택 날짜를 다시 눌러 해제함 (R2)
- 검색어를 입력만 한 상태, 공백만 남긴 상태, 날짜·검색어·리뷰 필터를 함께 적용한 상태 (R3)
- 전체 기록이 없음과 조건에 맞는 기록만 없음. 사진이 없거나 같은 날짜의 식사가 여러 개임 (R4)
- 일부 음식만 리뷰했거나 결과가 null인 재료가 있음. 사진만 있고 음식 결과는 없음 (R5)
- 연결 추천이 없거나 한 음식에 여러 개임. Serving Tip 내용이 없음 (R6)
- 삭제 확인 취소·연속 요청·요청 실패. 삭제할 식사가 추천의 원본이거나 마지막 시도 식사임 (R7)
- 음식이 없거나 결과가 모두 null인 식사, 모든 음식이 Eaten인 식사 (R8)
- 추천 0개·pending 존재·모두 처리 완료. 음식 4개 중 생성한 3개 추천만 모두 처리한 경우도 완료로 판단 (R8)
- 추천 최초 조회 중·실패를 미생성으로 오인하거나, Linked Suggestion 유무를 생성 여부로 오인함 (R8)
- 추천 버튼 연속 클릭 또는 추천 처리 후 상세 복귀 시 표시 조건이 달라짐 (R8)

## Acceptance Criteria

핵심 검토 기준은 다음 8개이며, 세부 동작은 Requirements를 따른다.

### AC1 — 작성 재개 (R1)

Given 저장된 Meal ID가 없는 미완료 식전 초안이 있고<br>
When Continue Logging에서 Resume을 누르고 이어 작성을 선택하면<br>
Then 저장된 입력값과 단계를 복원한다. 초안이 없거나 complete이면 Continue Logging을 숨긴다.

### AC2 — 날짜·검색·리뷰 필터 (R2·R3)

Given 날짜·검색어·리뷰 필터를 지정했고<br>
When 검색을 제출하면<br>
Then 세 조건에 맞는 식사만 표시한다. 날짜 선택을 해제하면 표시 중인 월과 관계없이 전체 날짜를 검색한다.

### AC3 — 빈 목록 구분 (R4)

Given 목록에 표시할 식사가 없고<br>
When 조회 결과를 표시하면<br>
Then 검색어가 있으면 검색 결과 없음, 없으면 기록 없음 안내를 표시한다.
Go to Meal Check-in은 전체 기록과 검색어가 모두 없을 때만 표시하며, 달력·검색 조건은 유지한다.

### AC4 — 리뷰 여부와 미작성 결과 (R5)

Given 식사 상세를 열었고<br>
When 저장된 음식 결과를 표시하면<br>
Then 모두 미작성일 때만 Awaiting Review와 Continue Review를 표시한다.
하나라도 결과가 있으면 Reviewed이며 미작성 음식은 No record로 표시한다. 결과가 null인 재료는 별도 카드로 표시하지 않는다.

### AC5 — 연결 추천 확인 (R6)

Given 음식 카드에 연결된 추천이 있고<br>
When Linked Suggestion과 Go back to meal을 차례로 누르면<br>
Then 같은 카드에서 첫 연결 추천과 식후 결과를 전환한다. 연결이 없거나 재료 카드이면 Linked Suggestion을 숨긴다.

### AC6 — 삭제 확인과 연결 데이터 처리 (R7)

Given 식사 삭제 확인창이 열려 있고<br>
When 취소하거나 삭제를 확정하면<br>
Then 취소는 기록을 보존하고, 삭제 성공은 식사·음식·재료를 제거한 뒤 Meal History로 이동한다.
해당 음식을 원본으로 생성한 추천과 그 시도는 함께 삭제하고, 다른 추천의 마지막 시도를 삭제하면 TRIED를 SAVED로 되돌린다.

### AC7 — 추천 버튼 표시 (R8)

Given 식사 상세와 추천 조회가 완료되었고<br>
When View Suggestion 표시 여부를 판단하면<br>
Then Eaten을 포함한 추천 대상이 있고 생성된 추천이 없거나 pending이 있으면 표시한다.
리뷰·대상이 없거나 생성한 추천을 모두 처리했으면 숨긴다. 미생성 음식이 남아 있어도 완료 기준은 같다.

### AC8 — 추천 버튼 위치와 이동 (R8)

Given View Suggestion 표시 조건을 만족하고<br>
When 사진 위 리뷰 상태 행 오른쪽의 Continue Review와 같은 디자인의 버튼을 연속 클릭하면<br>
Then 해당 Meal ID의 추천 화면을 한 번만 연다. 돌아온 뒤에도 표시 조건을 만족하면 다시 진입할 수 있다.
