## 1. 적용 범위와 판정 순서

### 1.1 이 문서가 정하는 것

여기서 재료는 **아래 포함 기준에 해당하는 선택 항목**이다. ‘세계에서 요리에 쓸 수 있는 모든 것’, ‘누군가 집에서 사용한 적 있는 것’이라는 뜻이 아니다. 가공품의 경계는 앱의 정책 선택이며 자연과학적 정답이라고 주장하지 않는다.

- 재료 후보의 유일한 입력은 RDA 10.4 본문 3,366행이다. 이름 부록은 같은 원본의 한영 이름을 연결하는 데만 사용한다.
- ‘흔하다’, ‘낯설다’, ‘건강하다’, ‘아이가 좋아한다’, ‘재료 같아 보인다’는 분류 근거로 쓰지 않는다. 등장 횟수·판매 순위·Agent의 자신감도 쓰지 않는다.
- 드물게 쓰이는 식용 원물도 A01이면 포함한다. 반대로 누군가 조리에 사용했어도 명시적 제외 종류면 제외한다.
- 식품 제조업에서 사용한다는 사실만으로 제외하지 않는다. 전분·소금·기름도 제조에 쓰이기 때문이다. **제품 종류가 허용 범위에 있는지**로 결정한다.
- 특정 재료를 포함했다고 특정 연령의 섭취나 제한 조건 통과를 승인한 것은 아니다.

### 1.2 판정에 사용할 원본 정보

각 행에서 한국어 이름 전체, 영어 이름 전체, 식품군, 학명(있는 경우), 원본 코드와 위치를 함께 읽는다. 첫 쉼표 앞 이름이나 식품군 하나로 결론 내리지 않는다.

판정 전에 다음 사실을 기록한다. 모르는 값은 `UNKNOWN`으로 쓴다. 언급이 없다는 이유로 `없음`이라고 쓰지 않는다.

| 확인할 사실 | 기록할 값 |
|---|---|
| 원료 | 확인된 식물·동물·광물·물·가공 재료의 종류. 미확인이면 UNKNOWN |
| 식용 부위 | 전체·뿌리·잎·줄기·살·알·내장 등. 미확인이면 UNKNOWN |
| 제품 형태 | 원물·분말·전분·면·소스·빵·음료·완성 메뉴 등 |
| 처리 상태 | 생것·건조·냉동·삶음·튀김·염장·발효 등 확인된 값 |
| 명시된 배합 차이 | 밀·달걀·우유 첨가, 가당·무가당 등 원문에 실제 적힌 값 |

원문으로 사실을 정할 수 없으면 RDA 설명을 확인한다. 그래도 결정에 필요한 사실을 확인하지 못하면 U01로 보류한다. 외부 자료로 용어 뜻을 확인할 수는 있지만, 그 자료의 다른 재료를 후보로 수입하거나 일반 제품군 전체의 배합으로 확대하지 않는다.

| 순서 | 검사 | 결과 |

에이전트는 행마다 `INCLUDE / EXCLUDE / UNRESOLVED` 중 하나와 이름·이유·근거만 출력한다. A/E/U 번호, 대표 코드, ACCEPT/MERGE 여부는 출력하지 않는다. 같은 이름의 행을 최종 병합하는 단계는 사람 검토 뒤다.

| E06 | A02~A06에 없는 분리·정제 제조 원료 또는 식품 첨가 성분 자체 | 포도당·과당·유당 분말·당알코올·말토덱스트린·분리 단백질·첨가물 코드로만 식별된 물질. 전분·일반 소금·MSG 조미료·베이킹파우더·이스트는 A02/A03/A05에 명시한 허용 종류. 순수 젤라틴·한천은 식품용 겔화 조리 원료로 아래 고정 예외에 포함 |

E06 고정 예외: **식품용 순수 젤라틴과 한천**은 A03의 겔화 조리 원료로 포함한다. 디저트용 gelatin powder mix처럼 당·향료 등의 배합이 불명확하면 U01, 푸딩·젤리 완성품이나 그 전용 믹스로 확인되면 E03이다. 새로운 제조 원료를 이 예외와 비슷하다는 이유로 추가하지 않는다.

### 2.3 보류 사유

| ID | 보류 사유 | 해결 방법 |
|---|---|---|
| U01 | 제품 종류·원료·한영 대응·필수 배합 사실을 확인하지 못함 | 빠진 사실과 확인할 원본 위치를 기록. 자료를 확보한 뒤 같은 정책으로 재판정 |
| U02 | 제품은 식별했지만 현재 A/E 어느 정의에도 들어가지 않음 | 누락된 제품 종류를 기록. 사람이 정책에 포함/제외 규칙을 추가하기 전까지 보류 |
| U03 | 포함 여부는 정했지만 재료 단위·한영 표시 이름·통합 대상이 불명확 | 충돌하는 이름·묶음과 구분이 필요한 속성을 기록. 확정 전 공개 목록에서 제외 |

‘잘 모르니 제외’, ‘다른 재료와 비슷하니 포함’은 허용하지 않는다. 한 종류의 불확실성이 모든 재료를 자동 보류시키지는 않지만, 같은 정의를 공유하는 묶음 내부에서는 서로 다른 확정 상태로 모순되게 공개하지 않는다.

## 3. 같은 재료로 합치는 기준

### 3.1 먼저 포함 여부, 그다음 통합

EXCLUDE나 UNRESOLVED를 포함 후보에 합쳐 숨기지 않는다. 감자 튀김을 감자로, 과일 주스를 과일로, 포도당을 설탕으로 합치지 않는다. 포함 후보끼리만 다음 기준을 적용한다.

### 3.2 비교할 속성

같은 재료인지 판단할 때 아래 속성을 같은 순서로 비교한다. 한 속성이라도 **확인된 차이**가 있으면 다른 재료다. 결정에 필요한 속성이 UNKNOWN이면 U03이다. 학명·성분표가 항상 있어야 하는 것은 아니며 원문의 명확한 식품 이름으로 확인된 범위도 기록할 수 있다.

| 순서 | 유지할 차이 | 예시 |
|---:|---|---|
| 1 | 원료 생물/원료 종류 또는 명시된 혼합 원료 | 밀과 쌀, 닭과 돼지, 밀전분과 옥수수전분, 고구마 당면과 고구마·감자 당면 |
| 2 | 독립적인 식용 부위 | 고구마 뿌리·잎·줄기, 달걀 전체·흰자·노른자, 생선 살·알·내장 |
| 3 | 조리 투입 형태 | 원물·가루·전분·면·즙·장·두부·유부·기름·건과일. 도정 정도가 상품 구분인 백미·현미도 유지 |
| 4 | 재료 정체성을 바꾸는 보존·변환 | 생과일·건과일, 생선·염장 생선·훈제 생선, 생콩·발효콩, 우유·유당분해 우유 |
| 5 | 원문에 명시된 원료 첨가·배합 | 우유 식빵과 일반 식빵, 가당/무가당, 참치 기름 통조림/물 통조림. 표기가 없다는 이유로 무첨가·무가당으로 해석하지 않음 |

위 다섯 속성이 같다고 확인된 뒤에만 다음 메타정보를 제거하고 합친다.

| 제거할 차이 | 처리 |
|---|---|
| 같은 원료의 품종명 | 대양·조양 귀리, 신동진·삼광 백미 등을 통합. 다른 종이나 독립 식용 원료를 품종으로 추정하지 않음 |
| 산지·계절·재배법·등급 | 남해·서해 고등어, 한우 등급, 노지·하우스 재배를 통합. 다른 원료·부위 차이가 있으면 먼저 분리 |
| 단순 가열·해동·냉동 | 같은 당근의 생것·데침·삶음·찜을 통합. 기름·양념을 첨가했는지 결정에 필요하지만 알 수 없으면 U01 |
| 크기·성별·절단 모양·포장 | 같은 원료의 크기·암수·다짐·슬라이스·슈레드·용기 차이는 통합. 알·내장·껍질을 별도 분리한 항목은 부위 차이로 유지 |
| 곡물·견과·콩·향신료의 원료 보관용 건조 | 일반 원료의 생/건조 상태는 통합. 분말·볶음·배합 여부가 다르면 해당 차이는 유지 |

등록된 종류의 차이와 단순 품종의 차이는 사람 검토에서 명시한다. 예를 들어 쌀의 백미/현미, 옥수수의 메/찰/단, 콩의 대두/검은콩은 서로 다른 표시 개념으로 유지한다. 새 구분을 제안할 때는 `원료 구분 / 도정·가공 구분 / 단순 품종` 중 하나와 RDA 근거 위치를 기록한다. 결정하지 못하면 U03이며 Agent가 임의로 목록을 늘리지 않는다.

### 3.3 사람 검토 뒤 대표 행 선정

동일한 개념으로 확인된 행을 하나의 묶음으로 만든다. 그 안에서 다음 순서로 대표를 정한다.

1. 해당 가공 형태가 같고 단순 가열 전인 행을 우선한다. 가공 재료의 대표를 다른 원물에서 고르지 않는다.
2. 원료·부위·배합을 유지하면서 품종·산지·등급 꼬리표가 가장 적은 행을 우선한다.
3. 동률이면 원본 식품 코드를 문자열 오름차순으로 정렬해 첫 행을 고른다.
4. 대표 코드는 최종 병합 승인 뒤에만 정한다. 에이전트가 임의로 대표를 지정하지 않는다.

이 순서는 의미상 다른 재료를 자동 묶는 규칙이 아니다. 묶음의 의미 확인이 먼저다. 한영 이름이 같다는 사실만으로 동일한 개념이라고 결론 내리지 않는다.

## 4. 사용자용 한영 이름

- 대표 이름은 **원료/재료 이름 + 필요한 부위·가공·배합 차이**로 작성한다. 원문 쉼표 목록을 재배열해서 쓰지 않는다.
- 품종·산지·등급·생것/삶음·원본 색인은 이름에 넣지 않는다. 3절에서 유지하기로 한 차이는 반드시 표시한다.
- 한국어와 영어가 같은 개념을 가리켜야 한다. 서로 다른 부위나 가공품을 한쪽 언어에서만 넓은 이름으로 뭉개지 않는다.
- RDA 영어가 단순히 Mushroom, Ray처럼 넓으면 세부 이름을 확인한다. 확인되지 않은 영어 일반명·학명을 만들어 붙이지 않고 U03으로 남긴다. RDA의 명시된 로마자 식품명은 사용할 수 있지만 임의 음역은 금지한다.
- 같은 개념의 동의어는 별칭 테이블로 수입하지 않는다. 대표 이름 하나만 쓴다. 다른 개념인데 같은 표시 이름이면 구분어를 추가하고, 그 말이 근거로 확인되지 않으면 U03이다.
- 영문 첫 글자 대문자, 한글 NFC, 앞뒤 공백 제거와 연속 공백 정리는 기계적으로 검사한다. 이름 길이를 맞추려고 의미를 삭제하지 않는다.

| 원본 | 한국어 표시 이름 | 영어 표시 이름 |
|---|---|---|
| 귀리, 쌀귀리, 대양, 도정, 생것 | 귀리 | Oats |
| 멥쌀, 백미, 신동진, 생것 | 백미 | White rice |
| 소고기, 한우(1++등급), 등심, 생것 | 소고기 등심 | Beef loin |
| 고구마, 줄기, 생것 | 고구마 줄기 | Sweet potato stems |
| 전분, 감자, 가루 | 감자전분 | Potato starch |
| 달걀, 난백, 생것 | 달걀흰자 | Egg white |
| 우유, 유당분해우유 | 유당분해 우유 | Lactose-free milk |

## 5. 실제 실행 기록과 검사

에이전트에게는 이 기준 전문, [작업 지시문](agent-workflow.md)의 인용 블록, RDA 원본 작업 파일이 제공된다. 반환 형식은 원본 코드마다 `decision`, `name_ko`, `name_en`, `reason`, `evidence`다. `decision`은 `INCLUDE`, `EXCLUDE`, `UNRESOLVED` 중 하나다. 포함 행은 두 이름이 있어야 하며 제외·보류 행의 이름은 빈 문자열이다.

코드는 작업마다 원본 코드의 누락·중복, 결정값, 필수 이름·이유·근거의 존재를 검사한다. 이는 응답 형식의 검사이며 분류가 실제 정책에 맞는지 자동으로 증명하지 않는다. 같은 이름의 원본을 기계적으로 묶은 결과도 최종 병합이 아니다.

사람 검토에서는 원본과 판단 이유를 대조해 다음을 확인한다.

1. 포함·제외·보류가 이 기준과 일치하는지, 특히 김치·피클·육수·빵·가공품 경계를 확인한다.
2. 같은 이름으로 묶인 행에 서로 다른 원료·부위·가공·배합이 섞이지 않았는지 확인한다.
3. 한국어 이름 하나에 영어 이름이 여러 개인 항목과 보류 행을 해결한다.
4. 승인된 개념에만 대표 코드와 운영 ID를 부여한다. 사람 승인이 끝나지 않은 결과는 DB 적재용 확정본으로 표시하지 않는다.

### 6.2 기준 변경은 새 버전으로

1. Agent는 U02를 발견하면 사례·원문·충돌 규칙을 기록하고 나머지 작업을 계속한다. 실행 중 포함 종류나 예외를 임의로 늘리지 않는다.
2. 사람이 새 규칙 또는 변경을 정하면 정책 버전을 올린다. 바뀐 규칙 ID와 바꾼 이유를 기록한다. 문서의 reviewed by 주석은 분류 정책 전체에 대한 사용자 승인을 뜻하지 않는다.
3. 변경 대상 종류의 기존 INCLUDE/EXCLUDE/UNRESOLVED를 모두 찾아 재검토한다. 보류 행만 고치고 기존 결과가 새 기준에 맞는지 확인하지 않는 방식은 금지한다.
4. 결과표·사용자용 목록·집계·근거 파일을 같은 버전으로 갱신한다. 서로 다른 기준이 섞인 결과를 확정본으로 내보내지 않는다.
5. 에이전트가 이 기준을 참고해 답한 사실과 사람이 답의 정확성을 확인한 사실은 구분한다. 사람 검토 전 후보 수를 승인된 재료 수로 인용하지 않는다.
